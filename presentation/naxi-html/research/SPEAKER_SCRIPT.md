# Living Naxi｜HTML 展示讲稿

按当前 **21 页** HTML 页面顺序撰写。每页讲一个重点；遇到现场演示、真实截图或外链时，以实际画面和任务状态为准，不把尚未完成的功能讲成成果。

**01｜封面。** 各位评委好，我们的作品叫 Living Naxi，平台名称是 Naxi AI Studio。我们想做的是：人工智能赋能冷门绝学，纳西文化传承寓教于乐。面向校园美育，把东巴文字、纳西古乐和纳西打跳从“看过、听过”，变成学生能参与、能练习、能表达的课程体验。

**02｜数据来源。** 做文化教育，首先要回答资料从哪里来。项目目前能核对的材料包括东巴字形目录、古乐素材库、原游戏资源和研究问卷。它们的来源完整度不同，所以我们把实地调研照片和未补齐的书目、授权信息明确留作待核实，不用一张漂亮的图替代真实证据。

**03｜知识资源。** 现在的“知识库”不是一个万能聊天数据库，而是几类可以按任务读取的真实资源：字形 CSV 与图片、音乐 SQLite 与录音、舞蹈教学视频和口诀。字形已经登记五条；读音、逐条授权及部分音乐文化标签还需要进一步核验。Agent 只能在这些边界内使用材料。

**04｜预处理。** 原始素材不能直接变成课程答案。我们先检查文件能否读取、路径和格式是否正确，再整理结构化字段、制作适合网页使用的媒体副本，最后留下人工校对位置。当前程序已完成其中的文件检查、部分图像处理和素材读取；文化专家审核不能由模型自动代替。

**05｜课程转化。** 项目的第一步创新，是把文化资料转成可完成的学习动作。学生不是一次性读完一整本资料，而是在剧情中遇见内容、通过书页建立认识，再完成辨形、听辨和舞步练习。每一项活动都要能追溯到原始素材。

**06｜分析方法与产品。** 我们用用户路径分析串起“剧情—知识—练习—Agent”，用前后测题目观察知识变化，再用 TAM 量表均分探索接受度。产品因此以一个游戏学习系统为核心，向外连接三个独立的专业 Agent；没有虚构一个总控 Agent。

**07｜原游戏学习。** 这一页是原 Godot 项目迁移到 Web 后的真实画面。东巴章节有剧情和文化书，古乐章节用原游戏视频进行音乐辨识，打跳章节先看完整演示，再学三个已有舞步和口诀排序。学生可以退出、继续和重做；通关后才自然进入对应的 AI 学习延伸。上方标签可切换课程对照图。

**08｜学习闭环。** Learn 是先认识文化内容，Evaluate 是发现书写或曲谱中的问题，Create 是在理解基础上完成个人作品。我们强调反馈回到下一次练习，而不是用一次生成代替学习。三条链路成熟度不同：东巴评价仍是模型辅助判断，古乐音频由本地工具合成，视频质量需要人工验收。

**09｜课堂路径。** 在一节美育课里，教师可以先核对素材，再用游戏剧情导入，让学生练习、查看反馈，最后展示和讨论作品。这是我们设计的教学应用路径。当前已有可体验的游戏与 Agent 页面；正式教案、教师管理和跨校应用尚未建成。

**10｜技术架构。** 浏览器里的 React 和 TypeScript 承载原生 Web 游戏与三个 Agent 页面；Python 本地 API 负责输入校验、路由、任务和文件。Qwen 用于视觉或文本分析，Wan 用于异步视频编辑，MIDI 与 WAV 由本地程序生成。模型密钥只在服务端，游戏进度和作品元数据分别按现有机制保存。

**11｜创新与互补。** 《北京青年报》最近讨论以学院、联盟和人才培养为冷门绝学“制度兜底”，其中也提到纳西东巴文。我们做的是面向学生的 AI 赋能：把可核对的文化资源做成游戏课程，再让专业 Agent 提供练习反馈和创作工具。制度保障学术传承，技术拓宽校园参与，两者互补；AI 不代替研究者和文化专家。[报道原文（人民网转载）](https://edu.people.com.cn/n1/2026/1109/c1006-40830362.html)。

**12｜三个专业 Agent。** 三个任务需要不同工具。东巴文 Agent 比较指定目标字和玩家书写，不做通用 OCR；古乐 Agent 对曲谱识别结果先人工校对，再规划编曲和本地合成；打跳 Agent 以玩家本人视频和参考图创建异步编辑任务。它们共享服务和资源，但各自独立运行。

**13｜一次调用如何发生。** 玩家主动点击提交，Web 将输入交给 Python API 校验并防止重复请求，之后才进入对应的 Agent 或工具。东巴文返回结构化建议，古乐返回实际 MIDI/WAV，打跳先返回任务状态，成功后才有 MP4。Mock 回退会单独标明，不会写成真实 AI 结果。

**14｜学习结果。** 现有研究摘要中，东巴文字配对题正确率从 40.2% 到 72.3%，样本 112；古乐相关题从 27.9% 到 90.4%，样本 136，两者差异显著。但舞步识别从 13.2% 到 18.4%，同为 136 人，p=.296，未达到显著。音乐后测 A/B 都计为正确，题目也不完全等值，不能把这些数字说成严格因果效果。

**15｜TAM 探索。** 175 份完整量表中，易用性、有用性和使用意愿均分分别为 4.24、4.23、4.31 分，满分 5 分。路径图显示三者之间的正向关系，但这里用的是量表均分作探索性分析，不是正式潜变量 CFA，也不能由相关关系推出因果。

**16｜结果与问题。** 这一页看三个 Agent 的真实结果界面，同时也看它们的边界。东巴评分是视觉估计，古乐有限采样不能保证传统风格，视频生成还要复核身份、动作和服饰。下一步我们更需要带人工标注的书写样本、经核验的录音和真实课堂反馈，而不只是更多模型调用。

**17｜关键代码。** 截图展示的是三条链路的关键门槛：东巴双图输入和回退标记，古乐音符校对与 MIDI/WAV 合成，打跳异步任务创建和查询。这些代码说明功能如何运行、如何拒绝不可靠输入；它们本身不等于模型输出已达到文化专家水平。

**18｜风险与建议。** 面向学生使用时，文化准确性和个人媒体安全必须放在前面。我们会补齐字形、录音和服饰的出处与授权；学生照片和视频须经本人同意；密钥留在服务端，视频任务按状态查询而不重复创建。对于拿不准的文化内容，页面应显示待核实。

**19｜应用界面。** 这里可以切换三条真实操作界面：选择目标字并临摹、上传曲谱并校对、上传本人视频和照片并选择服饰背景。视频演示将以外部链接提供；录屏需要完整呈现输入、主动提交、状态和结果。若链接尚未配置，我们会明确显示待添加。

**20｜任务提示与入口。** 这三句是任务说明示例，不是让学生随意改写系统提示词。东巴文关注目标字差异，古乐强调人工校对后保留旋律，打跳强调本人视频是动作来源。每条任务都对应本地 Web 入口，输出只展示当前服务实际能返回的类型；没有公开部署网址时不假装有线上产品。

**21｜收束。** 我们希望学生不只记住几个名词，而是在一笔、一曲、一步里形成自己的文化经验。冷门绝学需要研究者长期守护，也需要年轻人在课堂上真正走近它。Living Naxi 还要继续补资料、做试教和验证效果；我们希望先把那条从“知道”到“亲手参与”的路铺出来。
